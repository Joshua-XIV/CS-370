# CS-370

What I actually built was the qtrain function, the training loop for the deep Q-learning agent. Each epoch starts the pirate at a random free cell and lets it pick either a random valid move or the move its neural network currently rates best, decided by the epsilon value that starts high and decays over time. Every move gets passed to the environment’s act method, which returns the next state, reward, and game status, and I use that to update win history and store the episode in replay memory. From there I pull a batch of past episodes, train the model on it, and sync a separate target network every 50 epochs to keep training stable. After around 390 epochs the agent reached a 100 percent win rate from every valid starting cell.

Working through this project connected a lot of what I learned this term to what computer scientists actually do day to day. Computer scientists build systems that take in information and produce useful, reliable behavior, which matters because those systems end up making decisions that affect real people, whether that’s a game agent, a recommendation engine, or something with higher stakes. My approach to this problem started with understanding the pieces I was given before writing anything, reading through TreasureMaze and GameExperience to see how rewards and training data actually flowed, since writing the training loop without that context would have meant guessing at behavior I could have just looked up.

On the ethics side, this project is a small sandboxed game, but the same deep Q-learning pattern scales to systems with real consequences, and that comes with responsibility to both the end user and the organization building it. To the end user, that means being honest about what a model can and can’t do and not deploying something undertested just because it ran without errors once. To the organization, it means documenting assumptions and decisions clearly enough that someone else, or future me, can pick the work back up and trust what it’s actually doing.
